# FinProof Delivery Roadmap

> **For agentic workers:** REQUIRED REPOSITORY CONTRACT: follow
> `docs/implementation/QUALITY_LOOP.md` for the one task selected by `STATUS.md`. Skills are
> optional execution aids and may not expand its scope, writable paths, ownership, or review gates.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a competition-ready, evidence-first financial-product agent through four independently verifiable phases.

**Architecture:** HyperCLOVA X creates a constrained QueryPlan; product-specific data contracts, a deterministic query engine, policy/evidence layers, and a strict API produce stable grounded answers. Official workbooks are immutable, artifacts are prebuilt, and evaluation mode has no live external-data dependency.

**Tech Stack:** Python 3.12, Pydantic, Polars/fastexcel, Parquet, DuckDB, FastAPI, httpx, HyperCLOVA X, pytest/Hypothesis, Ruff, mypy, Docker, GitHub Actions.

## Global Constraints

- Follow `AGENTS.md` and the frozen design.
- Use HyperCLOVA X as the only generative LLM in runtime/evaluation.
- Use strict TDD and independently reviewable commits.
- Do not alter official source files or expected audit values.
- Do not start the next phase until the current phase gate passes.
- Do not add P1/P2 scope before P0 gates pass.

## Phase sequence

### Phase 1 — Repository and data foundation

Plan: `2026-08-07-01-repository-and-data-foundation.md`

Deliver a reproducible Bronze/Silver/Gold build with source lineage, quality issues, public-fund grain correctness, and read-only DuckDB/Parquet artifacts.

### Phase 2 — Deterministic query/evidence engine

Plan: `2026-08-07-02-deterministic-query-engine.md`

Deliver strict QueryPlan validation, explicit top-k scope, native cross-product ExecutionBundle segmentation, identity resolution, allowlisted SQL, exact operations, metric/state/comparability policy, evidence, claim verification, and stable Korean rendering independent of HCX.

### Phase 3 — HyperCLOVA X planner and evaluation API

Plan: `2026-08-07-03-hcx-planner-and-api.md`

Deliver one validated planner boundary with a provider-safe HCX schema plus strict local validation, bounded fallbacks, exact `/answer`, operational controls, Docker, and end-to-end tests.

### Phase 4 — Evaluation and release

Plan: `2026-08-07-04-evaluation-and-release.md`

Deliver reviewed golden cases, measured quality/ablation/latency/resilience, independent review closure, clean-room reproduction, and immutable submission assets.

## Review cadence

After each task:

```bash
python tools/check_repo_root.py --expected-root .
git diff --check
git status --short
```

After each phase, run the phase gate in `docs/implementation/PHASE_GATES.md`, request independent review, and merge only when all BLOCKER/HIGH findings are resolved.
